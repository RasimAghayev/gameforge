# Contributing

## How to contribute

1. Report bugs and feature requests using the issue templates in `.github/ISSUE_TEMPLATE/`.
2. Fork the repo, create a branch named `phase-<n>/<topic>` from `preview`, implement your change, and open a PR against `preview`.
3. Follow Conventional Commits (`feat`, `fix`, `refactor`, `perf`, `test`, `build`, `ci`, `docs`, `chore`, `revert`); one logical change per commit.
4. `make verify` must be green before a PR is reviewed.
5. Maintainers merge only after CI is green.
6. Never use `--no-verify`.
7. **No AI attribution in commits or PRs — ever.** No co-author trailers or "generated by AI" markers. Authorship is Rasim's alone.

## Development setup

- `make up` — start local services (Postgres, Mongo, Redis, NATS, Nginx) after `make verify`.
- `make shell` — open a shell inside the service container.
- Code is written only inside `projects/worktrees/<repo>/` (see `CLAUDE.md`/`PROMPT.md`).

## Review process

One PR per phase per repo. Maintainers merge after CI is green. Branch protection is enforced on `preview`, `test`, and `main`.
